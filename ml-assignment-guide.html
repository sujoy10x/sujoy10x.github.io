Before you start

A few ideas that show up everywhere

Read this once, and every part below will make more sense — these four ideas are reused across all five algorithms.

Supervised learning

You have the "right answer" for every example (a house price, a species label). The model learns by comparing its guesses to the truth. Parts 1–4 are all supervised.

Unsupervised learning

No right answers are given. You just hand the algorithm raw points and ask it to find structure on its own. Part 5, K-Means, is unsupervised.

Features & targets

A feature (input, predictor, x) is something you already know — a house's median income. A target (output, y) is what you're trying to predict — the house's value. Training a model means: show it many (features, target) pairs and let it learn the pattern connecting them.

Why we split into train / test sets

Testing a model on the exact data it learned from is like grading a student on the homework questions you already gave them the answers to — it can just memorize. Instead we hide a chunk of the data (the test set) during training, and only use it afterward to check whether the model generalizes to examples it has never seen. An 80/20 split means 80% of rows train the model, 20% are held back purely for grading it.

Why random_state=42

Splitting or shuffling data usually involves randomness. Without a fixed seed, you'd get a different split every run, making results hard to compare. Setting random_state=42 means "use this exact sequence of randomness every time" — the number itself is arbitrary, 42 is just a popular convention — so results are reproducible.

Part 01 · 10 marks

Linear Regression

Can a straight line predict a house's value from its neighborhood's income?

The idea

Linear Regression answers: "If I know one number about something, can I predict another number using a straight line?" Here: if I know a neighborhood's median income, can I predict its median house value? The model searches for the slope and intercept that make the line pass as close as possible to every real data point — minimizing the sum of squared vertical distances, which is why it's called "least squares."

y = slope × x + intercept

Setup (given)

fetch_california_housing(as_frame=True) downloads ~20,000 California housing blocks, each with 8 features (income, house age, rooms…) and a target, MedHouseVal — median house value in $100,000s. as_frame=True gives it to us as a pandas DataFrame, like a spreadsheet with named columns.

Q01

See the feature names

print(california_data.feature_names)

Prints the column names of the inputs only (not the target), so you know what data is available: MedInc, HouseAge, AveRooms, AveBedrms, Population, AveOccup, Latitude, Longitude.

Q02

Pick one feature and the target

x = df[['MedInc']].values
y = df['MedHouseVal'].values

df[['MedInc']] uses double brackets on purpose. Single brackets would give a 1-D Series; double brackets keep it a DataFrame with one column, which becomes a 2-D array after .values. Scikit-learn's models expect inputs shaped (rows, features) — even with 1 feature, it must be (20640, 1), not (20640,).

Check: x.shape → (20640, 1), y.shape → (20640,).

Q03

Scatter plot

plt.scatter(x, y, alpha=0.3, s=10)

Each dot is one neighborhood: x-position = income, y-position = house value. alpha=0.3 makes dots semi-transparent — with 20,000 overlapping points, transparency reveals density instead of one solid blob.

Q04

Fit the line

lin_reg = LinearRegression()
lin_reg.fit(x, y)

slope = lin_reg.coef_[0]
intercept = lin_reg.intercept_

.fit(x, y) is where learning happens: scikit-learn solves the least-squares equation for the best slope and intercept. coef_ is an array (one weight per feature — here just one, hence [0]); intercept_ is where the line crosses the y-axis.

Q05

Draw the line on top of the data

x_line = np.linspace(x.min(), x.max(), 100).reshape(-1, 1)
y_line = lin_reg.predict(x_line)
plt.plot(x_line, y_line, color='red')

np.linspace creates 100 evenly-spaced x-values spanning the income range — a "ruler" to draw across. .reshape(-1, 1) reapplies the 2-D shape the model expects. plt.plot (not scatter) connects the 100 predicted points into a continuous red line over the Q3 scatter plot, so you can visually judge the fit.

Part 02 · 10 marks

Logistic Regression

Is this flower a setosa or a versicolor?

The idea

Despite the name, this is used for classification, not predicting numbers. It estimates the probability that an example belongs to a category, by combining features into a weighted sum (like linear regression) and squashing that sum through an S-shaped curve — the sigmoid function — that forces the output into 0–1, so it reads as a probability. A rule then converts probability to a class: above 0.5 → class 1, otherwise class 0.

Setup (given)

Loads the classic Iris dataset — 150 flowers, 3 species, 4 measurements each — into a DataFrame data.

Q06

Peek at the data

data.sample(5, random_state=42)

Randomly grabs 5 rows to sanity-check the data before modeling it. random_state=42 makes "which 5 rows" reproducible.

Q07

Visualize relationships with a pairplot

sns.pairplot(data, hue="Species")

Draws every feature against every other feature as a grid of scatter plots (histograms on the diagonal), colored by species — a fast way to eyeball which features best separate the classes. For Iris, petal length and width are famously excellent separators.

Q08

Encode labels, drop one class

le = LabelEncoder()
data["Species"] = le.fit_transform(data["Species"])
data = data[data["Species"] != 2]

LabelEncoder maps each string to an integer alphabetically: setosa→0, versicolor→1, virginica→2. Then data["Species"] != 2 is a boolean mask — True/False per row — and indexing with it keeps only the True rows. Net effect: every virginica flower is dropped, leaving a clean binary problem, which is what plain Logistic Regression needs.

Q09

Separate inputs from target, then split

x = data.drop("Species", axis=1)
y = data["Species"]
x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.2, random_state=42)

axis=1 means "drop a column," not a row, leaving only the 4 measurement columns as x. train_test_split shuffles and splits x and y together, keeping each row's features matched to its correct label.

Q10

Train and check accuracy

log_reg = LogisticRegression()
log_reg.fit(x_train, y_train)

y_pred = log_reg.predict(x_test)
accuracy_score(y_test, y_pred)

.fit() learns a weight per feature (coef_) plus a bias term (intercept_) defining the decision boundary. .predict(x_test) classifies test examples the model never saw. accuracy_score counts the fraction classified correctly.

Setosa vs. versicolor are visually distinct — expect accuracy at or near 100%.

Part 03 · 20 marks

Support Vector Classifier

What's the widest possible gap you can draw between two classes?

The idea

Like logistic regression, SVC draws a boundary between two classes — but with a different philosophy. Instead of just finding any separating line, it finds the line with the widest possible gap (margin) to the nearest points of each class. Those nearest points are the support vectors — the only points that actually define the boundary.

The parameter C controls strictness about points crossing into the margin:

Small C — soft margin

Tolerates some points inside the margin (or even misclassified) in exchange for a wider, more generalizable margin.

Large C — hard margin

Punishes margin violations heavily → a narrower margin that hugs the training data tightly, which can overfit noisy data.

Setup (given)

Takes 2 of Iris's 4 features — petal length and petal width — standardized with StandardScaler (rescales each to mean 0, std 1). This matters for SVMs specifically: margin geometry is sensitive to feature scale.

Q11

Reduce to 2 classes

y_full = iris["target"]
mask = y_full != 2
X_bin = Xstan[mask]
y_bin = y_full[mask]

Same masking trick as Q8: mask marks every non-virginica row True; applying it to both Xstan and y_full keeps only setosa/versicolor rows in both, staying aligned row-for-row.

Q12

Visualize the two classes

plt.scatter(X_bin[y_bin == 0, 0], X_bin[y_bin == 0, 1], color='blue')
plt.scatter(X_bin[y_bin == 1, 0], X_bin[y_bin == 1, 1], color='orange')

X_bin[y_bin == 0, 0] reads as: "from X_bin, take rows where y_bin equals 0, and column 0 (petal length) of those rows." Common NumPy pattern for plotting classes one color at a time.

Q13

Train/test split

x_train, x_test, y_train, y_test = train_test_split(
    X_bin, y_bin, test_size=0.2, random_state=42)

Same 80/20 pattern as before, now on the two-feature X_bin/y_bin.

Q14–15

Train the SVM and draw its boundary + margins

svm_clf = LinearSVC(C=1, loss="hinge")
svm_clf.fit(x_train, y_train)

w = svm_clf.coef_[0]
b = svm_clf.intercept_[0]
decision_boundary = -w[0]/w[1] * x0 - b/w[1]
margin = 1 / w[1]

loss="hinge" is the hinge loss function — it only penalizes points on the wrong side of the margin; correctly classified points outside it cost nothing. This is what produces "maximum margin" behavior.

The boundary is defined by w·x + b = 0. To draw it on a 2-feature plot, we solve for petal width in terms of petal length — plain algebra rearranging w0·x0 + w1·x1 + b = 0 into x1 = -(w0/w1)·x0 - b/w1. The two dashed "gutter" lines are this same line shifted up and down by margin = 1/w[1].

Then svm_clf.predict(x_test) + accuracy_score check performance on unseen data, same as Part 2.

C = 1

Wider, more relaxed margin — tolerant of points near the boundary.

C = 1000

Narrower margin that sits closer to the data — much less tolerant of margin violations.

Comparing the two plots is the whole lesson of Part 3: C trades off "fit the training data tightly" against "keep the margin — and generalization — wide."

Part 04 · 30 marks

Bagging

Can many mediocre models, averaged together, beat one good one?

The idea

Bagging = Bootstrap Aggregating. A single model trained on one dataset can be noisy or biased by quirks in that particular sample. Train many models, each on a slightly different random resample, then average their predictions — individual errors tend to cancel out. It's the same principle as asking 100 people to guess the jellybeans in a jar and averaging their guesses: individual guesses are noisy, but the average lands close to the truth.

Bootstrap sampling: from a training set of size n, randomly draw n new rows with replacement — after picking a row, put it back, so it can be picked again. Some rows appear multiple times; some don't appear at all (~63% of unique rows get included on average). Each bootstrap sample is a different "view" of the same data.

Setup (given)

Reloads California Housing into reg_dataset, with feature columns and a price(target) column.

Q16

The bootstrap function + the real train/test split

def get_bootstrap_indices(n_samples):
    return np.random.randint(0, n_samples, size=n_samples)

np.random.randint(0, n, size=n) generates n random integers between 0 and n-1, with repeats allowed — "sample with replacement," via indices. Using them to index x_train[indices] produces the bootstrap resample.

The real 80/20 train_test_split happens once here, separately — the true held-out test set every model in this section is fairly graded against. Bootstrapping only ever touches the training portion.

Q17

Train model 1 on a bootstrap sample

model_1 = LinearRegression().fit(x_train_1, y_train_1)
pred_1 = model_1.predict(x_test)
mse_1 = mean_squared_error(y_test, pred_1)

An ordinary Linear Regression, but trained on a resampled version of the training data. mean_squared_error averages (prediction - actual)² across the test set — squaring penalizes big errors more. This is our baseline: one model's error, alone.

Q18–20

Add models 2, 3, 4 — and average

model_2 = LinearRegression().fit(x_train_2, y_train_2)
pred_2 = model_2.predict(x_test)

avg_pred_2models = (pred_1 + pred_2) / 2
mse_2models = mean_squared_error(y_test, avg_pred_2models)

Each question trains one more model on a brand-new independent bootstrap sample, then averages its predictions with all previous ones (element-wise). Watch MSE across Q17→Q20: it typically drops or stabilizes as more models join the average — bagging's variance-reduction effect, made concrete one model at a time.

Q21

Generalize into a loop over ensemble sizes

def bagging_experiment(n_models, x_train, y_train, x_test, y_test):
    train_preds, test_preds = [], []
    for i in range(n_models):
        idx = get_bootstrap_indices(len(x_train))
        model = LinearRegression().fit(x_train[idx], y_train[idx])
        train_preds.append(model.predict(x_train))
        test_preds.append(model.predict(x_test))
    avg_train = np.mean(train_preds, axis=0)
    avg_test  = np.mean(test_preds, axis=0)
    return mean_squared_error(y_train, avg_train), mean_squared_error(y_test, avg_test)

for n in range(2, 25, 2):  # 2, 4, 6, ..., 24
    train_mse, test_mse = bagging_experiment(n, ...)

This is the Q17–Q20 pattern, generalized: loop n_models times, each iteration drawing a fresh bootstrap sample and training a fresh model, stashing predictions on both train and test sets. np.mean(..., axis=0) averages across the list of models, keeping each row's average separate — exactly like the manual averaging above, for however many models you want.

Look for: training MSE stays low and roughly flat; test MSE decreases then flattens as the ensemble grows — diminishing returns, since bagging mainly reduces variance, not bias.

Part 05 · 30 marks

K-Means Clustering — from scratch

With no labels at all, can an algorithm find the groups on its own?

The idea

K-Means is unsupervised: give it unlabeled points and a number k, and it groups them by proximity — no correct answers shown. It alternates two steps until nothing changes:

1. Assign — put every point into the cluster of its nearest centroid.
2. Update — recompute each centroid as the average position of its assigned points.

Repeating assign → update → assign → update eventually stabilizes — that's convergence. Since k must be chosen ahead of time, the elbow method helps: run K-Means for several k values, measure cluster tightness (SSE), and look for the bend where adding more clusters stops helping much.

Setup (given)

points is a NumPy array with just petal length and petal width for all 150 Iris flowers — deliberately without species labels, since K-Means never sees them.

Q22

Find the nearest centroid to one point

def closest_centroid(point, centroids):
    distances = [np.sqrt(np.sum((point - c) ** 2)) for c in centroids]
    return int(np.argmin(distances))

For each centroid, squared differences per dimension, summed, then square-rooted — the standard Euclidean distance formula: √((x₁-x₂)² + (y₁-y₂)²). Computed against every centroid; argmin returns the index of the smallest — i.e. which centroid is nearest.

Q23

Recompute a centroid from its assigned points

def compute_new_centroids(clusters):
    for cluster_id in sorted(clusters.keys()):
        new_centroids.append(np.array(clusters[cluster_id]).mean(axis=0))
    return np.array(new_centroids)

clusters is a dict like {0: [point, point, ...], 1: [...]}. .mean(axis=0) averages down each column separately (average petal length, average petal width) — giving a new center point that's the "average location" of that cluster.

Q24

Pick reproducible starting centroids

def initialize_centroids(seed, p):
    np.random.seed(seed)
    indices = np.random.choice(len(points), size=p, replace=False)
    return points[indices]

np.random.seed(seed) fixes randomness so the same seed picks the same starting points. replace=False picks p genuinely distinct indices — real data points chosen at random to kick off the algorithm.

Q25

Measure clustering quality (SSE)

def compute_sse(centroids, clusters, k):
    for cluster_id in range(k):
        sse += np.sum((cluster_points - centroid) ** 2)
    return sse

Sum the squared distance from every point to its own cluster's centroid, across all k clusters. Low SSE = tight, well-defined clusters. High SSE = loose, scattered ones.

Q26

The full algorithm — combining Q22 & Q23

def kmeans(p, data, initial_centroids):
    centroids = initial_centroids
    while True:
        clusters = {i: [] for i in range(p)}
        for point in data:                        # 1. assign
            idx = closest_centroid(point, centroids)
            clusters[idx].append(point)

        new_centroids = compute_new_centroids(clusters)  # 2. update

        if np.allclose(new_centroids, centroids):     # 3. converged?
            break
        centroids = new_centroids
    return centroids, clusters

The heart of K-Means. Each lap: assign every point to its nearest centroid (Q22), update every centroid to the mean of its assigned points (Q23), then check whether anything moved (np.allclose). If nothing changed, stop — the arrangement has stabilized. Otherwise, loop again with the new centroids.

Every lap should make the clusters a little tighter (lower SSE) until it settles.

Q27

Elbow method

for k in range(1, 5):
    centroids, clusters = kmeans(k, points, initialize_centroids(42, k))
    sse = compute_sse(centroids, clusters, k)

Runs the entire pipeline once per k from 1 to 4, same seed each time for a fair comparison. Plotting k vs. SSE typically shows a steep drop from 1→2, then progressively smaller gains — the "elbow" is where the curve visibly bends and flattens.

Q28

Final run and visualization

best_k = 2  # chosen from the elbow plot
centroids, clusters = kmeans(best_k, points, initialize_centroids(42, best_k))

for cluster_id in range(best_k):
    plt.scatter(cluster_points[:,0], cluster_points[:,1], color=colors[cluster_id])
plt.scatter(centroids[:,0], centroids[:,1], color='black', marker='X', s=200)

With best_k chosen from the elbow plot, run the whole algorithm one last time: each cluster's points get their own color, final centroids are marked with large black X's — the payoff image, showing sensible groupings found purely from raw measurements, with zero access to true species labels.
