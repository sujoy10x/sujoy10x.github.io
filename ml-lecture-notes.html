Section 02

The Many "Shapes" of Data

Before building any model, what kind of data are you even feeding it?

Time series — 1 dimension

A single number changing along one axis — usually time, but not always. Heart rate over time, inflation over years, wind speed by season — even windmill height vs. power output counts, since it's one quantity changing along one axis.

📈
Case study — predicting ESG scores

A part-time PhD student (also a full-time company director) used language models to track a company's ESG score (Environmental, Social, Governance) over time as a time series — work that got accepted at ICML, a top ML conference. The lesson: a full-time job didn't stop world-class research.

Grayscale images — 2 dimensions

A computer never "sees" a photo the way you do — it sees a grid of numbers. 0 = pure black, 255 = pure white, everything between is a shade of gray. A grayscale image is just a 2D matrix of these numbers.

🔬
Case study — chip defect detection

Scanning electron microscopes photograph microscopic computer chips to check for defects — images come out grayscale and noisy. The model denoises them so real defects become visible instead of hidden in noise, enabling reliable pass/fail checks.

Color images — 3 dimensions

A color image is just three grayscale images stacked together — one each for Red, Green, and Blue. Mixing intensities produces every color: (255,0,0) = red, (0,0,0) = black, (255,255,255) = white.

🚗
Case study — autonomous driving

Moving cars capture blurry frames. Tasks like semantic segmentation (coloring pixels by what they represent) and object detection both perform worse on blurry input — so a deblurring model sharpens frames before detection happens, directly improving the safety pipeline.

Grayscale & color video — 3 & 4 dimensions

Video = many still frames played back-to-back. "30 frames per second" means 30 images shown every second — fast enough that your eyes perceive continuous motion. Grayscale video = 2D image + 1D time = 3D. Color video = 3D color image + 1D time = 4D.

Submarine periscopes (DRDO)

A rotating infrared camera captures blurry footage due to gimbal motion. The model converts blurry video into clean video for reliable analysis.

Pig health monitoring (UIUC)

Cameras track individual pigs' activity over time. Unusually inactive pigs get flagged early for quarantine, before disease spreads through the pen.

Quick reference

Data typeDimensionsFormula
Time series1Done changing quantity
Grayscale image2Dheight × width
Color image3Dheight × width × 3 (RGB)
Grayscale video3Dheight × width × time
Color video4Dheight × width × 3 × time
Beginner takeaway

Before choosing a model, always ask "what shape is my data?" — it instantly narrows which model families are even sensible to try. This idea returns later as inductive bias (Section 10).

Section 03

Why AI "Suddenly" Got Good

Most of this math existed before 1990. So why the boom around 2010–2015?

Two ingredients were missing for decades:

1. Not enough data

Before digital devices, data was stored on punch cards / paper rolls, read manually. Nowhere near enough labeled data existed to learn from.

2. Not enough compute

Early computers used bulky, failure-prone vacuum tubes — a single "computer" needed a whole room. Today's equivalent fits in your pocket.

What changed: every person online now constantly generates data — YouTube views, searches, photos, IoT sensors, digitized medical scans. At global scale, this becomes an enormous resource. Meanwhile, GPUs made it possible to actually process that much data.

CPU vs. GPU, in one line

A CPU might run 16 things in parallel; a GPU runs thousands. Processing 1 million images could take months on a CPU — a GPU does it in a fraction of the time. Like the difference between 16 teachers grading exams versus 10,000 teachers grading simultaneously.

Beginner takeaway: AI = (long-known math) + (big data, only recently available) + (GPUs, which made that data usable). None of the three alone was enough.

Section 04

The Central Problem: When Rules Don't Work

The philosophical heart of the whole lecture, taught through a live classroom exercise.

The postal code case study

A post office needs to sort mail automatically: a camera photographs each handwritten digit, and the system must classify it 0–9. The class was asked to write rules (no AI — just logic) to recognize the digit "2." Suggestions included: "a semicircle joined to a horizontal line," "a curved top with a straight bottom line," "should not contain a complete circle."

The catch: for every rule proposed, a real handwritten "2" broke it — no semicircle, no horizontal line, loops, sharp angles. No two people write digits identically.

The lesson

If a problem has a clean, provable relationship (like force = mass × acceleration), use rules. If a problem is impossible to fully capture with hand-written rules — because of too much natural variation — use a data-driven approach instead.

What ML does differently

  1. Collect many labeled examples of each digit (thousands of images labeled "this is a 2")
  2. Let an algorithm find the common pattern across all of them automatically — a pattern too complex and varied for a human to write down explicitly

This is why ML is also called pattern recognition (finding what separates categories), knowledge distillation (extracting essential knowledge from a huge pile of data), or data mining (extracting precious ore from raw rock) — same idea, different names.

Section 05

What Is a Neural Network, Really?

🧒
The toddler analogy

Teaching a toddler "yellow": the kid picks up a yellow block, says "yellow" — mother says "Good job!" The kid picks up green, says "yellow" — mother says "No, that's not yellow." Repeated correction, over and over, until the kid reliably recognizes yellow.

The mother = the supervisor. Try → get corrected → adjust. This is exactly supervised learning.

Computers don't have brain chemistry — they have numbers. So instead of a toddler's brain adjusting chemical connections, a computer model adjusts numerical parameters ("weights") until its output reliably matches the correct answer. That's "training a neural network" in one sentence.

Why "neural": the brain is made of connected neurons. An artificial neural network borrows the concept — many small connected units, each holding a number that gets adjusted during training.

Section 06

The 4-Step Recipe

The same four steps behind everything from simple linear regression to ChatGPT.

1. Collect a labeled dataset 2. Design a machine learning model (choose the function "shape") 3. Define a loss function (how do we measure "wrong"?) 4. Optimize the weights (make the model less wrong, repeatedly)

Every model is expressed as:

Y = F(X, W)

X = input · W = learnable weights (the "knowledge") · F = the model's shape (linear regression, CNN, Transformer…) · Y = predicted output.

Training = finding the best W. Once W is frozen, the training data can be discarded — the model is now a standalone deployable tool.

Step 1 — Collecting labeled data, in practice

  • Manual labeling — you're the domain expert on your own data
  • Public datasets — Kaggle, Hugging Face, and similar platforms
  • Outsourced labeling — services like Amazon Mechanical Turk
Section 07

Loss Functions

Teaching the computer "right" vs. "wrong."

A loss function is the computer's version of the mother saying "good job" or "no, try again" — a single number describing how wrong a prediction is. Low loss = doing well, high loss = doing badly. Training = adjusting weights until loss shrinks.

Classification — Cross-Entropy Loss

The model outputs a probability per class, summing to 1. True label: dog. Case 1 predicted dog at 0.775 → loss = 0.367. Case 2 predicted dog with higher confidence → loss = 0.095. Lower is better — Case 2 wins.

Intuition

Cross-entropy punishes confident wrong answers heavily, and rewards confident correct ones. 99% sure it's a dog, and it is → almost zero loss. 99% sure it's a cat, but it's a dog → punished hard.

Regression — Mean Squared Error (MSE)

For continuous outputs (price, temperature). Traffic cameras capture blurry violation photos; a model is trained on (blurry, clean) image pairs to sharpen future captures.

MSE = mean( (prediction − target)² )

Subtract element-by-element, square (removes negative signs, punishes big errors more), then average.

Classification vs. Regression

Classification

Discrete categories — hot/cold, spam/not-spam, digit 0–9

Regression

Continuous numbers — "feels like 29.5°C," house price, stock price

Section 08

Gradient Descent

How does the model actually find weights that minimize loss?

Closed-form solution

If you can take the derivative of the loss, set it to zero, and solve for the weights directly, you get the exact optimal answer in one shot — works for simple models like plain linear regression. For complex models (deep networks, Transformers), the math is often too complicated to solve this way.

Gradient descent (iterative)

🌄
The foggy hillside analogy

You're on a hillside in thick fog, trying to reach the valley floor. You can't see the whole landscape, but you can feel which direction is downhill from where you're standing. Take a small step downhill, feel again, repeat.

new_weight = old_weight − (learning_rate × gradient_of_loss)

Repeat this update over and over — loss should shrink a little each time, until the gradient is essentially zero (a low point reached).

The learning rate problem

Too large

You overshoot the minimum, bounce around, or the loss can even "explode" and get worse.

Too small

Training crawls forward extremely slowly, and can get permanently stuck in a shallow local minimum.

Imagine several valleys of different depths on your hiking trail: tiny steps might settle you into a shallow valley near your start and you'd never find the deep one elsewhere; huge steps might jump right over the deep valley into a random shallow one. The learning rate needs tuning — it's a hyperparameter.

Two kinds of "parameters"

TermMeaningExample
Learnable weightFound automatically during trainingSlope/intercept in Y = WX
HyperparameterChosen by you, before/around trainingLearning rate, iterations, k in k-means
Section 09

Data Challenges

A model is "only as good as its data" — the real-world messiness every dataset has.

Missing data

A form asking for both "birth date" and "death date" — for a living person, death date is blank, and that's expected, not an error. Never just delete rows — data is precious. Fix instead with:

  • Mean imputation — replace with the column's average
  • Median imputation — replace with the middle value (robust to outliers)
  • Nearest-neighbor imputation — fill based on the most similar other row

Errors vs. Artifacts

Errors

Natural, unavoidable noise during acquisition — camera noise in low light. Generally can't be fixed; inherent to the sensor/environment.

Artifacts

Systematic human mistakes — merging US/EU/India finance data without unifying currencies. Fixable — you introduced it, you can catch it.

Beginner takeaway: errors destroy information; artifacts create false information. Errors are noise to tolerate — artifacts are mistakes to actively hunt down.

Outliers

A point that deviates dramatically from the norm (one huge international-trip charge among months of routine grocery spending). Because loss functions sum error across every point equally, a single extreme outlier can drag an entire fitted line away from where it should sensibly sit.

Identifying outliers (IQR method)

Q1 = 25th percentile, Q3 = 75th percentile IQR = Q3 − Q1 Lower bound = Q1 − 1.5 × IQR Upper bound = Q3 + 1.5 × IQR → anything outside [lower, upper] is an outlier

Rather than deleting outliers (shrinking valuable data), a common fix is replacing them with the column's median — median resists distortion by extreme values, unlike the mean (in {2,2,2,2,3,3,3,1000000}, the mean is wildly skewed; the median stays sensible).

The Curse of Dimensionality

As you add more features (dimensions), you need exponentially more data to avoid "blind spots" — regions of feature space with no data at all. The same number of points looks densely packed in 1D, but scattered with visible gaps once plotted in 2D or 3D.

Evidence cited: MNIST (small 28×28 grayscale digit images) needed ~60,000 training images; CIFAR-10 (larger, more complex 32×32 color images, still 10 classes) needed considerably more — precisely because higher dimensions have more empty space to cover.

Practical implication

For a loan model with income, expense, savings — adding 3 × income as a 4th feature adds zero new information (fully predictable from income already), while making the dimensionality problem worse for no benefit. Keep dimensionality as low as the problem allows.

Section 10

Model Challenges

Overfitting vs. Underfitting

🐘
The von Neumann–Fermi story

Physicist Fermi excitedly showed his mentor von Neumann a 20-parameter model that fit his data with zero error. Von Neumann, unimpressed, replied (paraphrased): "With four parameters I can fit an elephant, and with five I can make it wiggle its trunk."

A complex-enough model can fit any training data perfectly — including all its noise — without learning anything real about the underlying pattern.

Case 1 — too simple

A straight line that misses the data's actual curve. Underfitting.

Case 2 — moderate

Captures the general trend without chasing every wiggle. Good fit.

Case 3 — too complex

Passes through every training point perfectly, but fails badly on new data. Overfitting.

Core lesson

Fitting the training data perfectly does not guarantee good performance on new data. The whole point of training is to perform well on data the model has never seen — not to memorize the training set.

Train / Validation / Test, and Cross-Validation

Standard split: 80% training, 20% held-out testing (never touched during training). But training loss keeps dropping the longer you train — even into overfitting territory. A validation set, carved from the training portion, catches this in real time: when validation error starts rising while training error keeps falling, that's overfitting beginning — often used as a signal to stop training early.

K-fold cross-validation

  1. Split training data into k equal folds (e.g., 10)
  2. Train on 9 folds, validate on the 1 remaining fold
  3. Repeat 10 times, using a different fold as validation each round
  4. Every data point gets used for both training and validation — never at the same time, so no data is wasted

Inductive Bias

🦆
Squirrel, duck, eagle

A squirrel climbs trees brilliantly but can't swim or fly. A duck swims brilliantly. An eagle catches flying prey brilliantly. None is "better" overall — each is suited to a specific task.

Every model architecture has built-in assumptions about what patterns it's good at finding — its inductive bias.

ModelStrengthGood for
CNNNearby pixels are related — local patternsVision: deblurring, segmentation
TransformerConnects distant/related pieces of infoLanguage, image captioning/Q&A
RNNProcesses sequences step-by-stepSequential/time-dependent data

Beginner takeaway: there's no universally "best" model — you match a model's inductive bias to your problem's structure, the same way you'd send a duck, not a squirrel, to fetch something from a lake.

Section 11

Evaluating a Model Properly

If 80 of 100 tumors are benign and a model predicts "benign" for everything, it scores 80% accuracy — while catching zero actual cancers.

This is class imbalance, and exactly why accuracy alone isn't trustworthy.

The Confusion Matrix

Actually PositiveActually Negative
Predicted PositiveTrue Positive (TP)False Positive (FP)
Predicted NegativeFalse Negative (FN)True Negative (TN)

Memory trick: the first word tells you if the model was correct; the second tells you what it predicted.

Why the "dangerous" mistake depends on the problem

🏃
Judge for a running race

A sprint and a marathon are both "races," but you'd never judge them the same way. Not every classification problem should be evaluated the same way either — it depends on which mistake costs more.

ScenarioDangerous mistakeWhy
Cancer diagnosisFalse NegativeTelling a sick patient "you're healthy" means no treatment — far worse than a false alarm
Anti-missile systemFalse PositiveFiring on a domestic aircraft mistaken for an enemy is catastrophic
Weather appRoughly equalMissing a rainy day and missing a nice day are both just annoying

The four core metrics

Accuracy = (TP + TN) / (TP + TN + FP + FN) Precision = TP / (TP + FP) → "when I said positive, how often was I right?" Recall = TP / (TP + FN) → "of all actual positives, how many did I catch?" F1 Score = harmonic mean of Precision and Recall
Choosing the right metric

Prioritize precision when false positives are costly (anti-missile — don't cry wolf). Prioritize recall when false negatives are costly (cancer screening — don't miss a real case). Use a weighted F1 if you need a blend leaning one way.

Section 12

The Three Flavors of Machine Learning

Supervised

Labeled input-output pairs. The loss function tells the model exactly how wrong each prediction was, every time. (Sections 5–11 all describe this.)

Unsupervised

No labels at all — the model finds structure (clusters, associations) purely from similarity in the data.

Reinforcement

No labels, but a reward/outcome signal — learning a whole sequence of decisions, evaluated only at the end.

🌸
Unsupervised — the flower show

Kids at a flower exhibition, given no names for anything, naturally group similar-looking flowers together and separate different ones — without anyone correcting them. This is clustering: grouping alike data, without ever being told the correct groups.

🛒
Unsupervised — grocery association

Working a month in a store, you notice: bread-buyers tend to buy butter and jam; biscuit-buyers tend to buy chips. Nobody labeled these relationships — you inferred them from repeated co-occurrence. This is association (the classic "customers who bought X also bought Y").

🛝
Reinforcement — the playground

A child at a playground isn't told the "correct" path to the slide. They explore multiple routes, hit crowds, try alternates, and eventually find an efficient way — learning a whole sequence of decisions, not a single right/wrong answer.

Chess analogy: a seemingly "dumb" intermediate move might be a deliberate sacrifice — you can't judge any single move in isolation, only the full sequence by whether the game was won. If the outcome is a win, that whole sequence ("policy") gets reinforced as good.

Quick comparison

SupervisedUnsupervisedReinforcement
Labels?Yes, every exampleNone at allNone, but a reward signal
FeedbackImmediate, every predictionModel finds structure itselfDelayed — after a full sequence
ExampleSpam vs. not spamGroup customers by similarityTrain an agent to win at chess
Section 13 · Hands-On

Case Study: Breast Cancer Classification

The live coding demo, reorganized into the standard ML workflow.

Roughly 1 in 8 women face a lifetime risk of invasive breast cancer — the real, high-stakes motivation for this classifier, built from scratch on a real diagnostic dataset.

Exploratory Data Analysis

1

Load and inspect

569 samples, 32 original columns. The ID column is a unique identifier with zero predictive value — dropped immediately.

2

Check scale differences

df.describe() shows wildly different ranges across columns (radius_mean maxes ~28; area_mean maxes ~2501) — an early signal that scaling will be needed.

3

Check missing values, duplicates, and class balance

31 numeric features + 1 categorical target, zero missing values, zero duplicates. Class split: ~62.7% benign vs. ~37.3% malignant — moderately imbalanced, which is exactly why accuracy alone won't be trusted later.

4

Univariate analysis and outlier detection

Histograms reveal skewed distributions; box plots (IQR method) reveal a substantial number of outliers across many columns.

Preprocessing

Golden rule

Split into train/test before applying any transformation. Computing statistics (mean, median, scaling parameters) on the full dataset lets test-set information leak into training — inflating results in a way that won't hold up in real deployment.

1

Separate features and target, encode labels

Malignant → +1, benign → −1 — models need numbers, not text.

2

80/20 train/test split

random_state=42 makes the split reproducible; stratify=y preserves the ~63/37 class ratio in both sets, so an unlucky split can't dump most malignant cases into just one side.

3

Handle outliers

Replaced with the column median (computed excluding the outliers themselves). Measured impact: accuracy rose from 95.6% → 98.2% after this single fix.

4

Handle missing values and scale

SimpleImputer(strategy='median') and StandardScaler — both use .fit_transform() on training data only, and .transform() (reusing training statistics) on test data, to prevent data leakage.

5

Remove highly correlated features

Features with correlation > 0.9 (e.g., radius_mean and perimeter_mean — a bigger radius mechanically implies a bigger perimeter) have one of the pair dropped. 30 features reduced to 20 — directly fighting the curse of dimensionality.

Training — two approaches, same model

Y = W0 + W1·X1 + W2·X2 + ... + Wn·Xn
Closed-form

Solves directly via XᵀXW = XᵀY — the exact optimal solution in one shot, no iteration.

Gradient descent

Iteratively updates weights via W_new = W_old − lr × gradient, repeated across many iterations.

The linear equation produces a continuous score; a threshold converts it to a class — score > 0 → malignant, score < 0 → benign (threshold is 0 here specifically because classes were encoded ±1; it would be 0.5 for a 0/1 encoding).

Learning rate, tested live

0.115 — too large

Looks like it's converging, then the loss suddenly explodes.

0.001 — too small

Barely moves even after 100 iterations.

0.01 — well-tuned

Training and validation loss decrease smoothly together — neither under- nor overfitting.

Cross-validation used Stratified K-Fold specifically, so every fold preserves the ~63/37 class balance. Both training approaches were evaluated with accuracy, precision, recall, and F1 — and converged to very similar performance, since they solve the same underlying linear model via two different mathematical routes.

Section 15

Key Takeaways

  1. AI is a tool for problems where writing explicit rules is impossible or impractical — not a replacement for rules when rules would actually work fine.
  2. Every supervised model, however complex, is really just: collect labeled data → design a model shape → define a loss → optimize the weights — the same four steps, at massive scale, for something like ChatGPT.
  3. Data quality usually matters more than model choice — missing values, outliers, artifacts, imbalance, and correlated features can all quietly sabotage a model. "A model is as good as its data."
  4. Never evaluate a classifier with accuracy alone — always ask which mistake (false positive or false negative) is more costly for your specific problem.
  5. Fitting the training data perfectly is not the goal — generalizing to new data is. Validation, cross-validation, and right-sized models all exist to protect against overfitting.
